# 随手传 V0.2：Windows 与 Android 配套应用

## 本次交付的定位

Windows 端提供当前用户安装器和便携版：自带 Node.js，双击启动后打开默认浏览器中的管理网页，关闭网页不会停止托盘中的服务，再次双击会复用当前实例。

Android 端是独立安装的轻量 App：原生连接页、离线二维码扫描、记住电脑地址、系统文件选择和下载，传输内容与反馈界面复用电脑提供的网页。它仍需要电脑服务运行；两端必须在可互访的网络中。

这保留了现有网页入口，也避免在电脑上再捆绑一套完整浏览器。Android App 使用自己的 WebView 会话，第一次需要重新配对，不能直接继承 Chrome 的登录。

## 与你电脑上 53 项测试版本的关系

本次可读取的远端基线为 `1743098`。用户报告中位于 `D:/Desktop/Codex/lan-relay` 的修复、测试和启动器尚未上传，本次没有读取或覆盖该目录。

应用包装在独立分支 `feature/native-apps-v0.2` 中完成，并依据报告补齐已知行为：默认设备名和预设、扫码回填本次连接码、已打开页面消费新的认证链接、保留启动失败退出码。Windows App 另行实现自动开页和重复启动复用。不能据此声称已经合并了不可访问的全部本机修改，测试数量也应分别记录。

**更新你现有源码工作区前，先由本机 Codex 比较并合并差异，保留未提交修改。安装器不应安装到这个源码目录。**

## Windows 开始使用

1. 下载当前构建的 Windows 工件，核对同包 `BUILD-INFO.json` 中的版本、源码提交和 `SHA256SUMS.txt`。
2. 选择安装器 `*Setup*.exe`，或者解压便携 ZIP；安装器按当前用户安装并创建桌面快捷方式。
3. 双击「随手传」，等待默认浏览器打开管理页面。托盘菜单可重新开页、查看数据位置或退出。
4. 保持电脑运行，在网页生成配对二维码，然后用安卓 App 扫码。

目标为 Windows 10 1903 及更新版本 / Windows 11，x64。Node.js 已随包提供；使用系统 .NET Framework 4.8，不要求用户安装 Node、npm、开发 SDK 或 Electron。

试用构建没有发布者代码签名证书；不能把“编译成功”描述成已取得 Windows 发布者信誉认证。使用者自行核对来源与摘要，不要关闭系统防护或整机防火墙。

### 服务与数据

- 应用数据默认在 `%LOCALAPPDATA%\LanRelay\data`，与旧源码版的 `.lan-relay-data` 分开。
- 首次启动会建立新工作区，不会自动读取、迁移或删除旧收件箱。
- 如需迁移，先停止旧服务和新应用，备份旧数据，再在确认目录结构一致后复制整个数据目录。不要在运行时复制 SQLite 数据库或混合两份数据。
- 默认端口仍为 `4318`；旧源码版正在使用时先正常停止旧服务。应用不得终止占用端口的其他进程。
- 关闭浏览器只是关闭页面；通过托盘退出才停止本应用启动的服务。
- 卸载和升级保留数据目录。没有自动公网转发或静默开机自启。

## Android 开始使用

1. 安装名称含 `android-trial.apk` 的试用包；`release-unsigned.apk` 是待正式签名的产物，不能直接安装。
2. 打开 App，选择扫码，按需授予相机权限，扫描电脑页面上的配对二维码；也可粘贴电脑地址或配对链接。
3. 第一次连接或切换电脑时确认目标地址；按系统要求授予局域网访问权限。
4. 设备名称默认「我的手机」，可选「我的平板」「另一台电脑」，或直接改成自定义名称。
5. 扫码会带入本次邀请的有效连接码；电脑批准后才能读取工作区。
6. 用系统选择器上传图片、文件或录屏。下载会交给系统下载管理器；“已交给系统”不表示已经保存、安装或测试通过。

设备名称有默认值，**配对码没有固定默认密码**。普通入口需要填写电脑当前显示的六位码，过期后重新生成。

### Android 的边界

- Android 17、target SDK 37 使用局域网运行时权限；拒绝权限时需要明确提示并允许重试，不绕过系统限制。
- 扫码使用离线库，不依赖 Google Play 服务或云端识别；相机权限仅用于扫码。
- 使用系统文件选择器，无全盘文件浏览或“所有文件访问”权限；不会为了上传原图而压缩或转码。
- 下载只处理已确认电脑的受控文件/反馈导出地址，认证检查失败时不把响应当作安装包。
- 不自动安装 APK、不进行 ADB 控制，也不宣称锁屏或后台能够永久持续上传。
- HTTP 局域网流量未加密；HTTPS 证书必须被系统信任，应用不接受忽略证书错误。
- App 关闭后会保留电脑地址和配对会话。退出登录或撤销设备后，应重新配对。

### 试用签名与后续更新

CI 生成的试用 APK 使用构建环境的开发证书，只用于验收。不同构建可能使用不同开发证书，不能承诺直接覆盖升级；不要卸载你已有的正式应用来强装试用包。应使用独立试用包名。

正式分发前，在你的本机生成并妥善备份长期签名密钥，用同一密钥签名后续版本。密钥、密码和证书私钥不得进 Git 仓库。本次不代替用户申请发布者证书，也不发布到应用商店。
