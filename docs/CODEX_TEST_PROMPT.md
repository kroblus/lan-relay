# 随手传 V0.1：交给本机 Codex 的测试提示词

将下面整段交给运行在 Windows 电脑上的 Codex。先打开本仓库；若还没有克隆，使用本次交付提供的已验证仓库地址。不要猜测或创建另一个同名项目。

---

你现在接手“随手传 / LAN Relay”V0.1 的本机测试与必要修复。请直接执行，不要只给测试计划。

## 目标与工作范围

这是电脑运行 Node.js 本地服务、手机用浏览器访问的局域网工具。主要流程是：扫码配对 → 双向传 APK/原图/录屏/文字 → 手机选择正在测试的构建 → 回传附件和一句反馈 → 电脑导出给 Codex 的材料。

先读仓库根目录的 AGENTS.md、README.md、docs/API.md、docs/VERIFICATION.md，核对实际代码和 Git 状态。保留已有未提交修改，不 reset/clean、不覆盖用户文件，不操作其他项目。测试证据统一放在本仓库 output/verification/ 下，不在主项目旁边新建一批平级工程。

可以修复测试发现的本项目缺陷。不要顺便增加云服务、远程桌面、全盘浏览、自动安装 APK、自动同步剪贴板等新范围。修复后只补必要回归。未经本轮另行授权，不 push、不发版、不公开部署。

## 1. 启动与自动测试

1. 记录实际 Windows 版本、Node 版本、浏览器版本、当前提交和工作区状态。项目要求 Node.js 24+，没有 npm 运行依赖，不应为启动而安装大量工具。
2. 执行 npm run check 和 npm test，保留命令、退出码和真实输出。失败就定位原因，区分环境限制与代码缺陷。
3. 用单独的 LAN_RELAY_DATA_DIR 启动测试实例，默认使用本仓库 output/verification 下的测试数据目录。不要使用或清理用户真实收件箱。
4. 验证 Windows 的 start.cmd、可选 .env 配置、端口占用提示、Ctrl+C 停止和再次启动。避免两个实例同时写同一数据目录。
5. 管理入口中的 owner 密钥、Cookie、CSRF token、配对 token 和有效二维码不得进入报告、提交、截图或公开日志。截图前关闭配对面板或使码失效。

若 PowerShell 仅因脚本执行策略拦截 `npm.ps1`，可以使用 `npm.cmd run check`、`npm.cmd test`、`npm.cmd start`，无需降低全局执行策略。启动可用 `node src/cli.mjs`。实际命令和退出码仍须记录。

## 2. 两个独立浏览器会话验证

使用两个隔离浏览器上下文模拟电脑与另一台设备；明确标注“浏览器模拟双端”，不能写成安卓真机通过。

- 未配对设备不能读取内容、文件、设备列表或创建配对邀请。
- 电脑生成连接二维码/六位码；另一端申请后，未经批准不能读取工作区。
- 批准、拒绝、失效、重复领取和撤销设备均符合实际状态；撤销后旧会话不能继续读文件。
- 已配对设备共享同一个私有工作区，界面不应伪装成隔离的私人聊天。
- 跨来源请求、错误 CSRF 和不允许的 Host 被拒绝；不用关闭浏览器保护来让测试通过。

## 3. 真实文件双向传输

用测试夹具完成电脑→另一端、另一端→电脑两个方向。至少包括：

- 一段带中文、俄文、换行、缩进的文字和一个正常 HTTPS 链接。
- 一张本地 PNG/JPEG 原图，下载后与源文件 SHA-256 一致。
- 一个普通 APK。优先使用我已有、明确用于测试的 APK，仅传输不擅自安装；没有真实 APK 时只做合成文件验证并标注限制。
- 一段 MP4 录屏或等价测试文件；预览不支持时仍能下载。
- 多文件队列、空文件、中文/空格/引号文件名、两个同名但内容不同的文件。
- 依据本机资源选一个至少跨越许多分片的大文件；若用 256 MiB 或更大夹具，记录大小及传输耗时。不要用内存堆满整个大文件。

验证进度、哈希准备阶段、取消、重试、重新选择原文件、下载文件位置说明。记录的“已发起下载”不能被解释成系统已落盘、APK已安装或验收通过。

## 4. 中断与恢复

- 上传到一半刷新页面或暂时停止网络，恢复后重选原文件，确认从服务端已提交位置继续。
- 尝试选同名同大小但不同内容的文件，必须因 SHA-256 不同而拒绝接续。
- 上传中途停止并重启服务，确认任务可恢复，已完成内容和反馈仍存在。
- 取消任务应释放对应临时内容；不删除原图、源 APK 或已经完成的其他文件。
- 检查磁盘配额与超限提示、损坏分片/不完整文件不误报成功。
- 下载端验证 Range 支持；手机浏览器是否能跨重启恢复，按实测结果记录，不推断。

## 5. APK 与测试反馈

- 不配置 Android SDK，先验证内置 APK 清单读取；可解析时显示实际包名、版本和 SDK 信息，不支持或无元数据时显示未知，不从文件名猜。
- 使用资源引用的版本名、SDK 预览代号、未声明的 debuggable 等字段不能被猜成具体值。内置读取失败且明确配置了安全可执行 SDK 工具时，才验证可选回退。
- 清单解析不代表签名有效或一定可安装。合成 .apk 夹具必须明确说明不可用于手机安装。
- 选择“当前测试版本”只影响后续反馈关联，不自动修改安装状态。
- 用户主动确认的安装/通过状态，与传输状态分开。
- 手机/第二会话上传截图或日志后，写一句反馈并关联附件；确认 buildId、附件和原话对应正确版本。
- 导出的 Markdown 包含原始说明、构建 SHA-256、已有元数据和可定位的本机文件路径；不编造机型、系统版本、复现步骤和测试结论。
- 同名新包上传后，旧反馈仍关联旧文件。

## 6. 页面与交互

验证桌面、320/375/430 px 宽度及 150% 文字。浏览器模拟与物理设备证据分别标注。

- 无横向溢出；长文件名、长链接、代码文本可阅读。
- 软键盘或窄屏下发送区和主要按钮不被遮挡。
- 文件拖放、图片粘贴、文件选择、多文件队列、文字发送、搜索/筛选、APK详情、反馈附件选择和导出操作真正可用。
- SSE 刷新不会吞掉正在输入的文字，也不会反复重置滚动或焦点。
- 加载中、未连接、服务停止、权限失效与空列表有清楚提示。
- HTTP 环境复制按钮有可用的手动回退，不能要求关闭浏览器安全设置。
- V1 不含 PWA 安装、系统分享目标或后台剪贴板同步；不要把这些未实现项当成本轮必须补齐的缺陷，HTTPS 也不会自动提供它们。
- 动画克制，处理大文件时页面仍可操作；不为修复而增加厚重后台表单。

## 7. 安卓真机验证

若已连接并获授权使用我的手机，先只读识别真实设备和浏览器版本；不要假设之前使用的系统版本仍然有效。使用现有授权，不主动开启无线调试或扩大权限。

手机和电脑处于可互访的局域网，优先用独立浏览器打开。验证实际扫码、配对批准、文字双向传输、原图与APK下载、手机录屏回传、切后台后恢复。

电脑有 VPN/代理时，检查是否允许局域网；不要直接关闭整机防火墙、证书验证或其他保护。不能读取网络名称时就让用户检查，不要编造诊断结论。

需要我操作相机、系统下载界面或手机安装器时，先完成全部可自动验证部分，再集中列出最少的人工步骤。没有实际真机证据时，结论只能是“待真机验证”，不可写 PASS。

- 如何启动当前可用版本及实际保存目录。

最后在聊天里给出简洁结论：第一版能否供我日常使用，是否存在阻止使用的问题，哪些操作还需要我完成。不要把“服务启动成功”当成全部功能已经通过。
