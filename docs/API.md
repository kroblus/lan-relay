# V1 contract (implementation authority)

Node 24 ESM built-ins, `node:sqlite`, no external npm packages. Native ES module browser UI. One private workspace: all paired devices share the same feed, not per-recipient chats. Owner can pair/revoke. Default port 4318, bind 0.0.0.0 for LAN. Files persist on host; mobile remains browser-based. HTTP development mode; optional configured trusted TLS.

## Server interface
`src/server.mjs` exports async `createRelayServer(options={})`, returning `{ server, store, ownerSecret, listen(port=0, host='127.0.0.1'), close() }`. `listen` resolves a Node address object; `close` closes SSE and HTTP connections and SQLite. Options: `dataDir`, `publicDir`, `maxFileBytes` (default 2 GiB), `maxStorageBytes` (default 20 GiB), `chunkSize` (default 2 MiB, integer 1 byte through 16 MiB), `allowedOrigins` (additional EXACT trusted origins for managed preview), `tls` optional `{key,cert}`, `apkAnalyzerPath` optional. Host interface addresses are discovered with os.networkInterfaces; no proxies are trusted by default. CLI defaults are port 4318 and host 0.0.0.0; the programmatic listen defaults above are intentionally loopback with an ephemeral port.

HTTP API returns JSON errors `{error:{code,message,details?}}`; never leak stack traces or secrets. Auth cookie `relay_session`, HttpOnly, SameSite=Strict, Secure under TLS; long random session tokens stored hashed. All authorized mutations require `X-CSRF-Token` returned by session API. Validate present Origin against request origin or explicitly configured exact origins. Reject hostile Host/DNS rebinding; permit loopback, local interface addresses and configured preview hosts. For no-Origin API clients require JSON on unauthenticated mutations. Never turn permissive CORS on. `GET /api/events` is authenticated SSE, event `change`, payload `{type}`; client refetches small relevant state. Add heartbeat, cleanup and reconnect.

## Identity
- `GET /api/health` -> `{ok:true,version:'0.1.0'}` (no sensitive data).
- `POST /api/session/owner` JSON `{secret,name?}` -> `{device,csrfToken}` and cookie. Bootstrap secret is generated/persisted outside git, printed by CLI in fragment URL `/#owner=...`, never exposed by unauthenticated GET.
- `GET /api/session` -> `{authenticated:false}` or `{authenticated:true,device,csrfToken}`. Device `{id,name,role:'owner'|'peer',createdAt,lastSeenAt}`.
- `POST /api/session/logout` -> clear cookie.
- `POST /api/pairing` (owner, CSRF) -> `{code,token,expiresAt,urls:[...]}`. A random 6 digit code and high entropy token, valid 5 minutes, single-use after successful request. URL fragment `/#pair=TOKEN`; front end picks network URL to QR encode. Owner UI can additionally construct current-origin link for proxy browser QA, marked as preview rather than LAN.
- `POST /api/pair/requests` (unauthenticated, rate limited) `{code? ,token?,name}` -> `{id,claimToken,status:'pending'}`. Only one of code/token. Secret claim token stays with requester, not owner list.
- `GET /api/pair/requests` owner -> `{requests:[{id,name,createdAt,expiresAt,status}]}` pending.
- `POST /api/pair/requests/:id/approve` or `/reject` (owner, CSRF) -> `{ok:true}`.
- `POST /api/pair/claim` (unauthenticated) `{id,claimToken}` -> `{status:'pending'|'rejected'|'expired'}` or `{status:'approved',device,csrfToken}` and cookie. Approved claim consumed once; retry with existing cookie can get session. Expiration also applies after approval. Store only hashed claim tokens.
- `GET /api/devices` -> `{devices:[...]}`. `DELETE /api/devices/:id` owner-only, owner-role devices cannot be revoked through this endpoint. Revocation invalidates peer sessions and streams.
- `GET /api/info` authenticated -> `{version,hostName,urls,port,secure,maxFileBytes,maxStorageBytes,usedBytes,chunkSize,apkAnalyzerAvailable}`. Data directory is included only for the owner. apkAnalyzerAvailable reports the optional external SDK executable, not whether the built-in parser exists; built-in manifest reading is always attempted for .apk files. Do not leak ownerSecret.

## Feed
- `GET /api/items?limit=200` -> `{items:[...]}` ordered by `createdAt DESC, id DESC` (max 200). For pagination send both `before=<last createdAt ISO>` and `beforeId=<last id>`; the two-field cursor includes remaining records at the same millisecond without duplicates. Legacy `before` alone retains strictly-earlier timestamp behavior. `beforeId` requires a valid `before`.
- Item `{id,kind:'text'|'file'|'feedback',createdAt,deviceId,deviceName,project,text?,name?,mime?,size?,sha256?,buildId?,attachmentIds?,note?,testStatus?,isApk?,apk?}`.
- APK metadata `apk` is `{status:'available'|'invalid'|'unavailable',source:'manifest'|'android-sdk',packageName?,versionName?,versionCode?,minSdk?,targetSdk?,debuggable?,note}`. Missing or resource-referenced fields remain absent, not inferred. Built-in manifest parsing supports UTF-8/UTF-16 and literal string/integer/boolean values; ZIP64, split-package dependencies, encrypted manifests and unsupported encodings return an explicit note. A successful metadata read is not APK validation.
- `POST /api/items/text` `{text,project?,buildId?}` -> `{item}`. Max 100000 Unicode characters, project <=80 chars, blank text rejected. Preserve content. URLs are text, client only opens http/https.
- `POST /api/feedback` `{text,project?,buildId?,attachmentIds?:string[]}` -> `{item}`. BuildId must reference an APK item if set; attachmentIds reference completed file items. Do not fabricate metadata.
- `PATCH /api/items/:id` `{project?,note?,testStatus?}` -> `{item}`. testStatus only for APK: `not-tested`, `user-confirmed-installed`, `issue-found`, `user-confirmed-passed`. Note max 5000 chars.
- `GET /api/feedback/:id/export` authenticated -> UTF-8 Markdown attachment with original text, known build facts, file names and host relative evidence paths; omit unknown device/installation facts explicitly. Escape Markdown injections in labels; no remote submission.

## Files and resumable upload
- `POST /api/uploads` `{name,size,mime?,sha256,project?,buildId?}` -> `{upload}`. SHA256 required lower/upper hex normalized; browser computes incremental SHA256 in a Worker before upload so original identity is checked on resume. Size safe integer 0..maxFileBytes. Reserve storage quota for active uploads. Original name validated/sanitized, storage name a generated ID; never execute or expose user paths.
- Upload `{id,name,size,mime,sha256,offset,status:'uploading'|'complete'|'failed',chunkSize,createdAt,project,buildId?,itemId?}`. GET `/api/uploads` -> `{uploads}` of this device; GET `/api/uploads/:id` -> `{upload}` only uploader/owner.
- `PATCH /api/uploads/:id` octet-stream, `Upload-Offset` header, CSRF. Body <= chunkSize and <= remaining bytes. On exact match append atomically; return `{upload}`. Reject concurrent/incorrect offset 409 with current offset in error details. Incomplete/overlarge request does not advance committed offset. Persistent SQLite offset; recovery truncates uncommitted tail or reports corruption; never announces false success.
- `POST /api/uploads/:id/complete` `{}` -> `{item}`. Require exact length; streaming SHA256 must equal expected. On match rename to immutable stored file and transactionally publish feed item. Idempotent completion. Incomplete/wrong hash rejected. APK metadata uses a built-in bounded ZIP/AXML reader (manifest compressed <=2MiB, output <=4MiB); if the built-in result is not available, optionally fall back to an explicitly configured executable Android SDK apkanalyzer, shell=false, bounded output/time. The SDK is not used to fill individual unknown fields when the built-in result is already available. Failed/unsupported yields explicit unknown note. Files by extension `.apk` get isApk true; metadata reading never proves signatures, installability or installed state.
- `DELETE /api/uploads/:id` cancel own pending/failed upload, release reserved disk and delete only its temp files. Cannot delete a completed file through this path.
- `GET/HEAD /api/files/:id` authenticated attachment; exact original safe encoded name via Content-Disposition; SHA256 ETag, Accept-Ranges: bytes, single Range supported (206/416), If-Range, Content-Length; no content execution. Inline preview only `/api/files/:id/preview` for allowlisted raster images/video/audio, no SVG/HTML/XML.
- `GET /api/files/:id/location` owner -> `{path}`; no arbitrary file read/write endpoints. Files all under controlled data directory.

## Frontend
`public/index.html`, `public/styles.css`, `public/app.mjs` owned by UI agent. `public/sha256.mjs`, `public/hash-worker.mjs`, `public/qr.mjs` owned by primitives agent. `sha256.mjs` export `Sha256` with update(Uint8Array)->this and hex()->string; `hash-worker.mjs`: post `{file,id}`, emits `{id,progress:0..1}` then `{id,sha256}` or `{id,error}`. `qr.mjs` exports `qrSvg(text)` returning an SVG string including a 4-module quiet zone, at least medium error correction, versions 1–12 and at most 256 UTF-8 bytes; longer values throw a RangeError and the UI falls back to the pairing code. No external request. Frontend never trusts raw user HTML and uses textContent. Current build per device session/localStorage is user's selection, not installed detection.

UI Chinese, warm off-white and coral accent, spacious but compact utility design. Main feed, composer, file drag/drop and paste, queue, filter, search, optional project chip, APK details and current testing selection, feedback with attachments. Owner connect panel QR/code, approval list, device revoke. HTTP limitations shown in compact connection details, copy fallback select text. Resume queue asks reselect original file and checks full SHA; persists upload IDs, file never base64. SSE updates/refetch preserving typed text. First-run owner sign-in via fragment; peer first-run name+code; empty state useful. No demo records in live database.

PWA installation, Web Share Target and background clipboard synchronization are not implemented in V1, even under HTTPS. Search/filter operates on records currently loaded in the browser; older records can be loaded in pages of up to 200. Windows startup and physical Android behavior require separate local verification; automated/browser-simulation results must not be presented as physical-device acceptance.
